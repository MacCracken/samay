# Getting started with samay

## Build / test / bench

```sh
cyrius deps                              # resolve stdlib + ai-hwaccel into lib/
cyrius build src/main.cyr build/samay    # compile the demo
./build/samay                            # run it
cyrius test                              # run the suite (416/416 assertions)
cyrius bench tests/samay.bcyr            # benchmarks
```

## Layout

samay is a **library** exposed as a single-file bundle:

- `src/*.cyr` — domain modules (`uuid`, `types`, `scheduler`, `cronexpr`, `cron`,
  `training`, `json`), in dependency order. That order is load-bearing: Cyrius
  resolves forward references in a single pass, and `dist/samay.cyr` is these
  seven concatenated.
- `src/lib.cyr` — include-only aggregation header (the whole-library entry).
- `src/main.cyr` — in-tree demo entry (excluded from the bundle).
- `dist/samay.cyr` — the committed bundle consumers include (regenerated by
  `cyrius distlib` from the `[lib].modules` list in `cyrius.cyml`).
- `tests/samay.tcyr` — tests · `tests/samay.bcyr` — benchmarks.
- `rust-old/` — the original Rust source, the parity oracle. **Do not modify.**

## Adding a feature

1. Edit the relevant `src/<module>.cyr` (or add a new module).
2. If new, register it in `cyrius.cyml` `[lib].modules` **and** `src/lib.cyr`,
   in dependency order.
3. Cross-check behavior against `rust-old/` (diverge only with an ADR —
   see [`../adr/template.md`](../adr/template.md)).
4. Add tests to `tests/samay.tcyr`; run `cyrius test tests/samay.tcyr`.
5. Run the cleanliness gate. **`fmt` and `lint` take a FILE argument** — a bare
   `cyrius fmt --check` prints usage, exits 0, and checks nothing:

   ```sh
   for f in src/*.cyr tests/*.tcyr tests/*.bcyr; do cyrius fmt "$f" --check; done
   for f in src/*.cyr; do cyrius lint "$f"; done   # want 0 warnings, 0 untracked deferrals
   cyrius test && cyrius bench tests/samay.bcyr
   cyrius distlib                                 # refresh dist/samay.cyr
   ```

   CI runs all of these, plus `cyrius distlib --check`, so a forgotten
   regeneration fails the build rather than shipping a stale bundle.
6. Bump `VERSION`, add a CHANGELOG entry, and update `docs/development/state.md`
   and [`../development/roadmap.md`](../development/roadmap.md) before tagging.

## Two things that will bite you first

**Strings are `Str`, not cstr.** Every samay API taking a name, id or expression
wants a `Str` (ptr+len), so wrap literals: `str_from("my-task")`. Passing a bare
literal **compiles cleanly and then segfaults**, because `str_data` reads the
literal as a ptr+len header. This is not hypothetical — it killed the benchmark
suite from v0.5.0 to v1.0.1 and the README's own example until v1.0.4. See
[ADR-0003](../adr/0003-str-string-representation.md).

**samay is single-threaded by contract.** One `TaskScheduler` / `CronScheduler`
per thread; serialise externally if you need to share one. There is deliberately
no internal lock — see [ADR-0008](../adr/0008-threading-contract.md). If your
process has more than one thread at all, call `samay_init()` once before spawning
(the constructors already do, so this only matters if you use the free cron
functions with no scheduler).
